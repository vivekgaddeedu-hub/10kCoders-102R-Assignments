Git & GitHub Version Control Assignment

Git Continuation & Collaboration

A comprehensive guide and demonstration covering cloning remote repositories, initializing local projects, linking remote GitHub origins, staging, committing, and verifying synchronization.

🔄 The 4 Areas of Git Architecture

Area 1

Working Directory

Your local sandbox containing untracked or modified project files on disk.

Area 2

Staging Area (Index)

Files prepped for the next snapshot via git add <file>.

Area 3

Local Repository (.git)

Permanent snapshots recorded in your local commit history via git commit.

Area 4

Remote Repository (GitHub)

Hosted cloud repository synchronized via git push & git pull.

Task 1

Clone an Existing GitHub Repository

git clone

Cloning copies an entire remote Git repository—including its commit history, branches, and tracked files—down to your local machine.

zsh • terminal
> git clone https://github.com/vivekgaddeedu-hub/10kCoders-102R-Assignments.git
Cloning into '10kCoders-102R-Assignments'... remote: Enumerating objects: 42, done. remote: Counting objects: 100% (42/42), done. remote: Compressing objects: 100% (35/35), done. remote: Total 42 (delta 8), reused 40 (delta 6), pack-reused 0 Receiving objects: 100% (42/42), 2.85 MiB | 4.12 MiB/s, done. Resolving deltas: 100% (8/8), done.
> cd 10kCoders-102R-Assignments && git branch
* main
  • ✓ Creates a dedicated directory containing the complete project and its hidden .git database.
  • ✓ Automatically sets up the default remote alias named origin pointing to the GitHub repository URL.
Task 2

Create and Initialize a New Local Repository

git init

To start version control on a brand-new or existing folder on your local system, initialize it with git init.

zsh • terminal
> mkdir my-collab-project && cd my-collab-project
> git init
Initialized empty Git repository in /Users/sudheergadde/my-collab-project/.git/
> git branch -M main
Branch renamed to 'main' as modern standard.
  • ✓ Generates the hidden .git folder to track commits, branches, and staging states.
  • ✓ Renaming the initial branch to main aligns with modern GitHub defaults.
Task 3

Link Local Repository to a GitHub Remote

git remote add origin

Connect your standalone local repository with an empty repository created on GitHub using the git remote add command.

zsh • terminal
> git remote add origin https://github.com/username/my-collab-project.git
> git remote -v
origin https://github.com/username/my-collab-project.git (fetch) origin https://github.com/username/my-collab-project.git (push)
  • ✓ origin is the conventional shorthand name given to the primary upstream server.
  • ✓ git remote -v confirms the fetch and push target URLs are properly configured.
Task 4

Add, Commit, and Push Changes

add • commit • push

Perform the fundamental snapshot lifecycle: stage tracked files, record a commit message, and transmit commits to the GitHub cloud.

zsh • terminal
> echo "# Collaboration Project" > README.md
> git add .
> git commit -m "feat: initial commit with project documentation"
[main (root-commit) 7a8bc91] feat: initial commit with project documentation 1 file changed, 1 insertion(+) create mode 100644 README.md
> git push -u origin main
Enumerating objects: 3, done. Counting objects: 100% (3/3), done. Writing objects: 100% (3/3), 280 bytes | 280.00 KiB/s, done. Total 3 (delta 0), reused 0 (delta 0), pack-reused 0 To https://github.com/username/my-collab-project.git * [new branch] main -> main branch 'main' set up to track 'origin/main'.
  • ✓ git add . stages all modifications and new files.
  • ✓ -u flag (upstream) binds your local branch with the remote branch for effortless future git push commands.
Task 5

Verify Changes Locally and on GitHub

status • log

Verify that working trees are completely clean, commit histories match, and remotes reflect the latest revisions.

zsh • terminal
> git status
On branch main Your branch is up to date with 'origin/main'. nothing to commit, working tree clean
> git log --oneline -n 3
